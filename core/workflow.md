# 完整工作流

入口顺序由 SKILL.md 定义，制作阶段只有资料缺失、A风格、B主视觉四处交互。反馈在交付后。遵循用户明确的流程豁免，其余按 checkpoints.md 等待实际回答。

## 01 INPUT · 内容理解

读 `core/input_validation.yaml`，提取标准活动记录：每项保存value、status（provided/inferred/pending/not_applicable/fictional）、source。P0=主题、语言、用途、尺寸；P1=日期、地点或线上入口、主办、简介、受众、报名；P2=Logo/二维码/照片/赞助/参考/品牌。

先用已给上下文确定，不反复问；资料完整也先集中核对事实、语言、用途、尺寸并确认；已有明确确认不重复问。P0缺失一次性补齐。P1集中询问，可明确标待定做预览，未决事项正式交付需确认；P2一起列成可补选项，可跳过。不要因线上活动无线下地点、免费活动无票价等反复阻塞。不默认编造；用户明确允许虚构时填充并记录范围，但语言/尺寸若并未授权自选仍需确认。

## 02 STRATEGY · 多维标签与联合匹配

读 `core/activity_tagging.yaml`：活动类型、内容主题、目标受众、情绪气质、传播场景，附每个标签的证据、置信度及是否推断。再把设计意图映射到构图、媒介、标题人格、明度这四类视觉参数；旧四维不替代五维活动理解。分类先读 ../libraries/styles/README.md：S1–S8为与用户附件一致的制作风格，M为锚点关系，摄影/斜向/字形/景深等拆为独立参数，不再混作同级风格或母版。

使用 `libraries/styles/packs.json` 与 `libraries/layouts/templates.json`，先判断每个风格是否存在能容纳实际信息的版式。用户明确风格或参考约束、禁用字体/素材是前提，不由总分抵消。T/M/A/C/R初始权重0.30/0.25/0.20/0.15/0.10，缺参考时移除R并归一；有明确参考时先看图判断compatible与证据，再计解释分，不伪装自动图像相似度。

主S控制空间、表面媒介、配色节奏与标题人格，骨架及具体参数另述依据；0–2辅助只借局部且检查冲突。没有无依据的S×M硬白名单；典型骨架倾向仅0.03软加分，非自然密度必须有实际容量证据。渠道适配须有本次评分证据，不按风格名臆测。按授权的新分类历史为重复风格/版式添加轻微惩罚，不能因此违背用户选择。`recommend_design.py`仅作候选筛选；优先呈现证据、冲突和代价，数值不作为最终决策；能给启发式排名，不能替模型看图、设计或代用户确认。低置信标签在A说明假设，不能强行确定。

**断点A**：展示1推荐+2–3替代、所选主辅关系、可行构图、每候选2条适配依据和1条代价；有实际参考时展示3张看过的图，无图如实说明文字指南与蓝图驱动，不虚构，询问确认/换风格/自定义，然后暂停。

## 03 COMPOSITION · 概念与无字主视觉

读 `core/layout_matching.yaml` 与 `core/generation_pipeline.yaml`。先读 libraries/layouts/matching.md，按已确认尺寸和标题/信息/主体选择V或H空间模式，记录选用理由与未选候选；不增加交互断点。A确认后细化信息密度、视觉形态、构图母版、标题/事实/Logo/二维码安全区。区域来自原画空间和可读性，不能变成救急色板。

先做准确标题粗排骨架（实际字数、断行、宽高、视觉重量），再为两版分别写：核心隐喻、主体造型、材质媒介、色彩光照、空间关系、标题位置。两版共享确认的主S，核心母题、空间组织、图字关系三项至少两项不同；不能只有换色。先读对应S指南并准备hero_a/hero_b提示词。把实际参考传入生成工具。主视觉默认不生成正式活动文字；后端支持时先低分辨率预览，选定再做高分辨率，不虚构接口参数。

看每版与参考的主体、空间、媒介和明度是否一致，记录差异及问题。**断点B**：展示无字候选、各自的标题位置示意及差异，等用户选择/修改；选择前不得做最终H0、正文与成品。标题占位仅用于验证图字关系，不当成正式标题。

## 04 PRODUCTION · 独立H0与真实合成

读 `libraries/typography/rules.json`、`libraries/typography/h0-typography.md`、`libraries/layouts/integrated-layout.md`。

准确标题→字体气质→路径选择→艺术字→逐字检查→透明同画布层。字体驱动可做有依据的切割、拉伸、纹理等，核许可并查字形；图像生成适合装饰标题，缺笔画/错字/不辨认必须修。图像H0不使用字库cmap报告冒充核字，也不声称能直接改字。

正文用合法字体精确排，中文英文各自调字距、行距和断行，共享视觉系统。文字直接融入选定主视觉，不用纯底条隔开。保留全尺寸无字hero、透明title、透明text。图层需同一坐标；小尺寸H0先在排版源中定位到完整画布再导出，不能要求用户手动对位。

`compose_layers.py`把这些真实输入合成，输出工程中的嵌入栅格层；它不能将已合成图片智能拆层。需要可编辑正文时另交真实文本SVG/排版文件，不能把嵌入PNG称完全可编辑。

## 05 QUALITY · 前置复核与局部修复

概念、主视觉、标题、合成各阶段复核，不积累错误到末尾。读 `core/quality_review.yaml`。

四硬项：文字准确性、可读性、图层完整性、内容完整性。记录PASS/FAIL/PENDING/NOT_RUN与观察证据；任一非PASS只能作预览。四硬项不能用设计分补偿。设计质量、风格一致性各1–5分附问题及修复依据，不是自动学习结果。

按真实文字alpha采样局部对比，正文比大标题更严格，另看完整尺寸和实际投放缩略图：

```bash
python scripts/check_text_readability.py --final poster_project/01_final/poster_zh.png --background poster_project/02_hero/hero_zh.png --text-layer poster_project/06_metadata/text_combined_zh.png --blocks blocks_zh.json --out poster_project/06_metadata/readability_zh.json
```

每个块记录实际位置、角色、大小与颜色；栅格标题字号保守估算并注明。像素算法不识字、不判审美，复杂效果有限；不能伪造PASS。失败优先移动/换行、颜色字重、适量效果及连续局部背景调整，不默认整图重生、加大底色、缩小主视觉。单问题最多两轮，仍失败说明局限并提供下一步，不静默交正式版。

## DELIVERY 与反馈

按 output.md 的六目录交成品、层、工程与元数据；`validate_output.py`全部通过才称正式交付。提供真实存在的文件，不把无图层的生成稿说成完整交付。

交付后按 ../feedback/rules.md 收集满意度和问题分类，定位模块并局部修改，复评后保存案例。没有回复就feedback_review；满意度是第四处交互，不阻塞已完成的交付；无依据不升级核心规则。未经授权不改安装目录，不把单次差评自动写成全局规则。

状态执行细节见 [checkpoints.md](checkpoints.md)。
